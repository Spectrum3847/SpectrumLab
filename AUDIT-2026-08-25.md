## 1. Machine walkthroughs — what's missing

### Scoring method
A page counts as having a walkthrough if it has a numbered, start-to-finish "Operating Instructions"
or equivalent procedure section — not just principles and safety rules.

### 1a. Machines with NO walkthrough (highest priority)

These are real machines with an SOP header, PPE badges, and a training requirement — but no numbered
run-the-machine procedure. A student who's never touched one cannot follow the page.

| Page | What's there now | What's missing |
|---|---|---|
| `cutting/sanders-grinders.mdx` | "Deburring Workflow" prose, technique notes | Numbered start-up → dress the wheel → cut → shut-down for the **belt sander**, **bench grinder**, and **Scotch-Brite wheel** separately. The 1×30 belt change is undocumented. |
| `forming/arbor-press.mdx` | Bearing/broach principles, alignment | Numbered press-a-bearing procedure and numbered broach-a-keyway procedure (setup, shim stack, when to stop, how to check) |
| `electrical/soldering-test-bench.mdx` | Technique prose, per-instrument sections | Numbered "solder your first joint" procedure; **Rigol scope**: how to actually get a trace on screen (probe, coupling, trigger, autoset); **DC supply**: set voltage + current limit before connecting |
| `electrical/wire-prep-crimping.mdx` | Tool-by-tool descriptions | Numbered Powerpole assembly procedure and a numbered hydraulic-lug crimp procedure |
| `electrical/coprocessors.mdx` | Shortest page on the site (68 lines) | Numbered SD-imaging steps (which imager, which OS image, where it lives), numbered static-IP/network setup, first-boot verification |
| `finishing/surface-prep.mdx` | Five good numbered *stages* | Fine as-is, but the blast/scuff stage needs the actual equipment steps |
| `cutting/drill-press-shear.mdx` | Has numbered procedures ✅ | **Missing: the belt/pulley speed-change procedure.** The page says "check the RPM chart inside the pulley cover" — document the actual chart. |
| `portable-power/dewalt-and-pneumatics.mdx` | Six tool sections | Track saw (DCS520) rail setup + plunge sequence is the one that needs numbering. Also **Quincy QT-5 daily start-up/shutdown and tank drain** — currently only on the maintenance page. |

### 1b. Multi-tool pages that hide per-tool procedures

`portable-power/m12-ecosystem.mdx` covers **17 tools** in one page with a single shared pre-flight
checklist. The nibbler, cut-off tool, band saw, jig saw and die grinder each deserve their own
short procedure (or their own page). Same issue, smaller scale, on the five `hand-tools/*` pages —
they're reference/where-it-lives pages, which is defensible, but **taps** and **rivnuts** in
`threading-riveting.mdx` genuinely need numbered procedures (tap drill selection → start square →
back off every half turn → oil; rivnut: size the hole → set → verify).

### 1c. Machines that HAVE good walkthroughs (leave alone)

WAZER, xTool MetalFab, Gweike M3, Thunder Nova 35, Titan 25T, lathes, evolution saws, bandsaws,
table saw, tapping machine, powder coating, curing oven, Cricut, heat press, HP T630, Bambu, Prusa,
M12 riveting. That's 18 of ~26 machines — the site's core is solid.

### 1d. Cross-cutting walkthroughs that don't exist as pages at all

These are workflows students actually need, currently scattered or absent:

1. **"I have a CAD file, how do I get a part?"** — a router page: which machine for which
   material/thickness/tolerance, and the file-format chain (STEP → DXF → machine).
2. **First day in the lab** — an onboarding path. There's no page that says "read these 4 pages,
   get these 3 sign-offs, then you can touch these tools."
3. **Pit setup / competition load-out** — T-Stak pit kits are described in `toolboxes.mdx` but
   there's no "what goes in the trailer and how it gets packed" procedure.
4. **Sheet metal end-to-end** — laser cut → deburr → bend on the Titan → powder coat. Each step is
   documented; the sequence and the "leave bend relief / mask before coating" handoffs are not.
5. **Aluminum tube-and-gusset workflow** — chop saw → drill/tap → rivet. Same argument.

## 3. Help tips, definitions, and student comprehension

### 3a. There is no glossary and no definition mechanism

The site uses a lot of vocabulary with zero support: *SFM, peck drilling, tap drill, kerf, k-factor,
bend allowance, backgauge, air assist, kiss cut, weeding, HTV, outgassing, QCTP, broach, live center,
carbide insert, Live-Z, elephant foot, purge tower, AMS, input shaping, Powerpole, ferrule, duty
cycle, tonnage, garnet mesh, DPI vs LPI.*

**Recommendation:** build a `<Term>` component (dotted underline + hover/tap popover) backed by a
single `src/data/glossary.json`, plus a `/reference/glossary/` page rendering the whole thing. One
data file, used everywhere, searchable. This is the highest-leverage single addition on this list —
it makes every existing page more readable without rewriting any of them.

### 3b. Calculators would beat prose in five specific places

The pages currently ask students to do arithmetic mid-task, which means they won't:

| Where | Calculator |
|---|---|
| Lathes / drill press | **RPM from SFM and diameter** — replaces two static tables |
| Titan 25T | **Tonnage + minimum flange + bend deduction** from material, thickness, die width |
| Threading | **Tap drill size** from thread + desired thread engagement |
| M12 riveting | **Rivet grip range** from stack thickness |
| Powder coating | **Cure countdown** from part mass/thickness with the double-coat rule |

### 3c. Concept explainers that are assumed, not taught

- **How to read a caliper and a micrometer** (with a photo of a reading and the answer)
- **How to read a drawing** — tolerances, datums, hole callouts, thread callouts
- **Fastener anatomy** — what 10-32 vs 1/4-20 vs M5 actually mean, head types, grade markings
- **Why aluminum grades matter** — 6061 vs 7075 vs 5052, where each is used on the robot
- **Feeds and speeds, conceptually** — why steel is slower, what a chip should look like
- **Thread engagement and why we don't over-torque into aluminum**
- **Material thickness reference** — gauge vs inches vs mm, one table

### 3d. Small in-page affordances worth adding

- **"New here? Read this first"** callout at the top of every machine page linking the PPE page and
  the required sign-off — currently the training requirement is buried inside the SOP box.
- **A difficulty / sign-off badge** in the page header: green (anyone) / yellow (orientation) /
  red (mentor sign-off). The `training=` prop already carries this information as prose on all 26
  SOP pages — promote it to a visible, filterable badge.
- **"Common mistakes"** section per machine. Only the tapping machine has one ("Common failures")
  and it's one of the most useful sections on the site.
- **Unit toggles** — the site mixes inches, mm, PSI, °F. At minimum be consistent per page.
- **Photo captions already do a lot of teaching** — that pattern is working; extend it to the
  photos you shoot for §2.

## 4. Site and workflow improvements

### 4a. The data you already have, unexploited

`src/data/storage-locations.json` (22 KB, fully catalogued) is read by exactly **one** component and
**one** page. Meanwhile the site's most-repeated user question is "where is X?"

> **Build a `/find/` page**: one search box over every drawer, bin, case and shelf in
> `storage-locations.json` + `consumables.json`. Type "reamer" → "Orange Toolbox drawer 9". This is
> a few hours of work against data that already exists, and it's probably the most-used page on the
> site once it exists.

Related: **QR codes on the physical drawers and machines** that deep-link to the relevant page or
drawer anchor. The label-maker standard is already documented — extend it with a QR column.

### 4b. Low-stock flagging is a dead end

`inventory/consumables.mdx` tells students to "post it in Slack." That's a workflow with no receipt
and no queue. Options, cheapest first:

1. A "Report low stock" link per row that opens a **pre-filled GitHub issue** (item name, part
   number, location, reorder URL). Zero infrastructure, permanent record, assignable.
2. A Slack webhook via a Cloudflare Worker function.
3. Quantity + reorder-point fields in `consumables.json` with a `/inventory/low-stock/` view.

The same argument applies to **maintenance logging** — `maintenance/schedules.mdx` has a "Reporting &
logging" section with nowhere to actually log.

### 4c. Print and offline

**There are no print styles** (`custom.css`, 628 lines, zero `@media print`). Pre-flight checklists
and SOPs get printed and taped to machines — that's the whole point of the PM-1130V placards already
in `public/signage/`. Add:

- `@media print` rules: drop nav/sidebar/TOC, black on white, expand links
- A **"Print this checklist"** button on `PreFlightChecklist`
- **Extend the signage system beyond the lathe.** `public/signage/` has placards for the PM-1130V
  only. Every red-tier machine should have one, and `Graphics/safety-icons/` (9 badges, 9 glyphs,
  a working `generate.py`) is built and ready — **but it's untracked in git and unused by the site.**
  Commit it, then wire the badges into `MachineSOP.astro` to replace the emoji PPE badges.

### 4d. Consistency issues found

- **PPE badge rendering uses emoji** (🥽 ⚠️) while a proper ISO-7010 icon set sits uncommitted in
  `Graphics/`. Wire them up.
- **12 pages have no photos at all** (§2a) — including three of the four Graphics pages.
- **`maintenance/schedules.mdx` is 416 lines**, the longest page on the site, and covers ~25 machines
  in one scroll. Consider splitting by cadence or surfacing each machine's schedule on its own page.
- **`index.mdx` machine grid omits the tapping machine** and the fiber-laser overview page.
- **Blue toolbox "CNC Router" drawer** — see §2d; the ShopSabre is gone.
- **`CHANGE-REQUEST-machine-cleanup-and-manuals.md` appears fully applied** — the files it asks to
  delete don't exist. Worth deleting the handoff doc so it stops looking like open work.

### 4e. Things worth building if there's appetite

- **Training sign-off tracker** — the site defines sign-offs for 26 machines but has no record of who
  has them. Even a static roster page beats the current nothing.
- **Machine status board** — down / needs-attention / ok, per machine, on the homepage.
- **Per-machine "settings we've proven"** — the laser and printer pages have these; the lathe,
  saws and Titan don't. Aggregate them into one settings reference.
- **Mobile check** — never verified. Students use this on phones in the shop, standing at a machine.
  Verify the drawer maps, wide tables and the consumables filter UI at 375 px.
- **Search quality** — Starlight's default search indexes prose but not `consumables.json` or
  `storage-locations.json`. If §4a's `/find/` page happens, this matters less.
